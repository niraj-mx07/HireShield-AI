# HireShield-AI Frontend Architecture & Engineering Documentation

This document provides a comprehensive technical overview of the **HireShield-AI** frontend application. It documents the implemented codebase, component hierarchy, design system tokens, state management, interactive workflows, and prototype limitations as they exist in the repository today.

---

## 1. OVERVIEW

**HireShield-AI** is an AI-powered opportunity-credibility assessment platform designed to protect students, freshers, and job seekers from fraudulent job offers and recruitment scams. This frontend repository contains a high-fidelity single-page application (SPA) built for interactive project demonstrations. 

> [!IMPORTANT]
> **Prototype Scope Disclaimer**: This application is a client-side mock frontend populated with realistic sample datasets. It **deliberately does NOT** connect to a live backend API, execute real web verification requests (WHOIS, DMARC, DNS, SOS DB), parse uploaded PDF files, or persist user data in a database. All authentication state is simulated via a local React Context boolean toggle.

## 4. DESIGN SYSTEM SUMMARY & DRIFT ANALYSIS

### Configured Tokens in `tailwind.config.js`

  - `font-sans`: `Plus Jakarta Sans`, sans-serif (Weights 400, 500, 600, 700 for all UI, buttons, badges, and evidence text).

  - `secondary`: `#506354`, `secondary-container`: `#d0e5d2`

  - `ink`: `#1c1b1b`, `ink-muted`: `#414941`, `ink-subtle`: `#717970`
  - `risk-low`: `#1e5631`, `risk-low-bg`: `#d0e5d2`
  - `risk-moderate`: `#b45309`, `risk-moderate-bg`: `#fef3c7`
  - `risk-high`: `#ba1a1a`, `risk-high-bg`: `#ffdad6`
  - `accent-recruiter`: `#5521b5`, `accent-recruiter-bg`: `#edebfe`
  - `accent-document`: `#9d174d`, `accent-document-bg`: `#fce7f3`
  - `accent-url`: `#0369a1`, `accent-url-bg`: `#e0f2fe`
- **Shapes & Shadows**:
  - `borderRadius['2xl']`: `16px`
  - `boxShadow.subtle`: `0 4px 20px -2px rgba(28, 27, 27, 0.05), 0 2px 6px -1px rgba(28, 27, 27, 0.03)`
  - `boxShadow.floating`: `0 12px 32px -4px rgba(0, 62, 28, 0.08), 0 4px 12px -2px rgba(28, 27, 27, 0.04)`

### Design System Drift Analysis (vs `docs/Frontend/Design.md`)
1. **Omitted Hover Tokens**: `primary-hover` (`#18512c`) and `on-primary-container` (`#8fca9b`) specified in `Design.md` were not configured in `tailwind.config.js`; UI elements use `hover:bg-primary-container` or `hover:bg-surface-2` instead.
2. **Omitted Tertiary Tokens**: `tertiary` (`#003d28`), `tertiary-container` (`#00573a`), and `on-tertiary-container` (`#40d399`) from `Design.md` were omitted from the Tailwind configuration.
3. **Surface Scale Simplification**: `Design.md` specified 4 surface levels (`surface-1` through `surface-4`). The codebase simplified this to `surface` (`#ffffff`) and `surface-2` (`#f6f3f2`).
4. **Borders**: Dedicated border tokens (`border`: `#c0c9be`, `border-strong`: `#717970`) were omitted; components apply borders via Tailwind arbitrary opacity classes (e.g. `border-ink/5` or `border-ink/10`).

## 7. STATE & MOCK DATA

### React Auth Context (`frontend/src/context/AuthContext.jsx`)
Provides global state across all components:
- `isLoggedIn` (boolean, default `false`).
- `activeReport` (object, default `mockAnalysisHighRisk`).
- `toggleAuth()`: Flips `isLoggedIn` boolean.
- `loadReport(reportData)`: Updates `activeReport` payload.

### Mock Data & Helper ([`frontend/src/data/mockData.js`](file:///Users/nihar/Desktop/CodeGround/HireShield-AI/frontend/src/data/mockData.js))
- **Predefined Assessment Payloads**:
  - `mockAnalysisHighRisk`: Score 88, DON'T APPLY (Apex Global Solutions, equipment check fraud).
  - `mockAnalysisModerateRisk`: Score 52, HOLD (Vanguard Tech Partners, third-party agency, high salary).
  - `mockAnalysisLowRisk`: Score 12, APPLY (Stripe, Inc., 100% verified corporate domain & DMARC).
- **History List (`mockHistoryList`)**: Array of 8 realistic past analyses.
- **Shared Count Helper (`getScanCounts(analyses = mockHistoryList)`)**:
  ```javascript
  export const getScanCounts = (analyses = mockHistoryList) => {
    const list = Array.isArray(analyses) ? analyses : [];
    let highRisk = 0, moderate = 0, verifiedSafe = 0;
    list.forEach((item) => {
      const level = item.riskLevel || (item.score >= 61 ? 'high' : item.score >= 31 ? 'moderate' : 'low');
      if (level === 'high') highRisk++;
      else if (level === 'moderate') moderate++;
      else verifiedSafe++;
    });
    return { total: list.length, highRisk, moderate, verifiedSafe };
  };
  ```
  Both `DashboardPage` and `HistoryPage` consume `getScanCounts(mockHistoryList)` to guarantee identical totals (**8 Total, 3 High Risk, 2 Moderate, 3 Verified Safe**).

## 8. KEY INTERACTIVE FLOWS

### 1. Submitting an Analysis Flow
1. User enters text on `/analyze` or clicks `⚡ Load High-Risk Sample` / `⚡ Load Verified Safe Sample`.
2. Form submit invokes `loadReport(selectedPayload)` and navigates to `/analyze/processing`.
3. `ProcessingPage` initiates sequential `setTimeout` timers (500ms intervals), updating step completion checkmarks and progress bar percentage.
4. After 3,600ms, `ProcessingPage` triggers `navigate('/analyze/result')`.
5. `ResultPage` reads `activeReport` from Context and renders the SVG gauge, risk factors, and matrix items.

### 2. Guest vs. Authenticated Mode Toggle Flow
1. User clicks `Simulate Login` in the Header (or on guest callout banners in `/dashboard`, `/history`, `/analyze/result`).
2. `toggleAuth()` flips `isLoggedIn` in Context.
3. React re-renders `/dashboard` and `/history`, switching from locked preview views (`<Lock />` icon container with login prompt) to full authenticated metrics, Recharts graph, and data tables.

### 3. Viewing a Saved History Report Flow
1. User navigates to `/history` while logged in.
2. Top 4 StatCards render full unfiltered counts (`counts.total = 8`, `highRisk = 3`, `moderate = 2`, `verifiedSafe = 3`).
3. User types in search bar or selects a filter pill (`All Scans (8)`, `High Risk (3)`, `Moderate (2)`, `Verified Safe (3)`).
4. Search/filter state updates the table list below while the 4 top summary StatCards remain fixed on full totals.
5. Clicking any history row calls `loadReport(item.payload)` and navigates to `/analyze/result`, populating the report view with that item's data.

## 9. KNOWN LIMITATIONS

1. **No Real Backend API Integration**: All analysis results, risk scores, and extracted evidence are static mock objects.
2. **In-Memory State**: Refreshing the browser resets `isLoggedIn` back to `false` and resets `activeReport` to default.
3. **Mock Processing Sequence**: The scan checklist animation is driven by fixed local `setTimeout` timers rather than real network polling.
4. **Mock PDF Download**: Clicking `Download PDF` triggers a visual toast banner (`Mock PDF Report generated successfully!`) rather than generating a PDF blob.
5. **Simulated File Upload**: Selecting a file on the Document tab displays the file name without parsing PDF text or sending binary payloads.

## 10. HOW TO RUN

All commands must be executed from inside the `frontend/` directory:

```bash
# 1. Navigate to the frontend directory
cd frontend

# 2. Install dependencies
npm install

# 3. Start local development server (bound to port 3000)
npm run dev -- --host 127.0.0.1 --port 3000

# 4. Build production bundle
npm run build

# 5. Preview production build locally
npm run preview
```
